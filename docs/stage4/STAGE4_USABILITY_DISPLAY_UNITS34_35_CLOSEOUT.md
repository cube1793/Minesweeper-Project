2026-11-09 (Asia/Seoul). A는 등록 시험·독립 검토와 현재 PC의 사용자 native 보고 범위에서 수용한다. B는 최종 기능 시험이 통과했지만 표시 비용 기준을 넘어서 채택하지 않았다. 현재 작업 트리는 검증된 A snapshot과 같다.

## A에 반영한 범위

- worker와 부모의 permit 기한을 동일한 monotonic ns 기준으로 맞췄다. nonce·세대·소비 토큰과 만료 검증을 유지한다.
- 실패 문구가 terminal ACK의 정상 정리 문구로 덮이지 않게 했다. 실패 기록은 해당 Stage4 owner와 ACK 상태에 결속된다.
- 종료된 자기 owner의 정리 재시도를 지원한다. 보유 handle의 PID·생성 시각·scope를 확인하며, V1/K의 정리 권한은 확장하지 않는다.
- 분석 계산 중 Auto 인수와 추측 설정 변경 뒤 재개를 확인했다. 원 입력 ACK와 정리 이후 최종 설정으로 재개하며 OFF·새 게임·정책·Replay 전환은 예약을 취소한다.
- 계산 경과 시간을 표시하고 28px 상급 보드를 위한 창 크기를 조정했다. 경과 시간은 완료율 추정치가 아니다.
- Auto와 추측 허용은 별개 설정이다. Auto를 켜도 사용자의 추측 허용 값을 임의로 켜지 않는다.

제품 변경은 `live_policy_job.py`, `stage4_live_contract.py`, `stage4_live_job.py`, `stage4_live_ui.py`, `stage4_live_worker.py`, `ui_manager.py`다. 관련 시험 5개 파일을 포함한 A 변경은 총 11경로다. 수학·S/M/R 목적·표본/후보·기본 indexed와 명시 K100K는 이 변경 범위 밖이다.

## B의 표시 기능과 비용

B는 기존 공개 root/base/facts를 재사용하여 입력 뒤 최신 안전칸·지뢰칸·확률 표시를 만드는 후보다. 최종 24파일과 patch는 output에 보존했으며 현재 제품에는 적용하지 않았다.

등록 측정은 같은 프로세스에서 A_ON/B_ON/B_OFF를 워밍업한 뒤 9개 block의 정방향·역방향 순서를 교차했다. 동일한 공개 입력, 실제 디스크 wire, projection·표시·offscreen paint를 포함한다. 표시용 추가 counter/model 0과 선택·입력 동일은 이 통제 수순의 근거다.

| 보드 | 중앙값 증가 | 중앙값 허용 | 배치 P95 증가 | P95 허용 |
| --- | --- | --- | --- | --- |
| 9×9 | −0.144875ms | 1ms | +3.592695ms | 3ms |
| 16×16 | +3.705606ms | 1ms | +4.781056ms | 3ms |
| 30×16 | +6.535634ms | 1ms | +9.311159ms | 3ms |

허용치는 중앙값 `max(A×5%, 1ms)`, P95 `max(A×10%, 3ms)`다. 여기서 P95는 9개 배치의 입력당 평균값 중 최대값이며 개별 입력 지연 분포 전체의 P95가 아니다.

9×9에는 블록 내 실행 위치 효과가 있어 차이의 부호가 바뀐다. 16×16·30×16은 두 실행 모두 9/9 block에서 B가 더 느렸고, 독립 검토는 미채택 판단을 유지했다. 일반 정책 불변·실전 효율·전체 Stage4 속도에 대한 수용 근거는 아니다.

사용자는 필수 worker 신원·기능·현재 Job 종료 확인과 과거 전체 프로세스 신원 전수 감사를 분리하도록 승인했다. 새 gate는 실제 요청 원장의 필수 owner, 생성 handle·PID·생성 시각·이미지·Job, 종료와 자원 회수를 확인한다. 성공한 Job 조회 두 번에서 active/member 0을 요구한다.
