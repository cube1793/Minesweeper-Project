# Stage 4 Unit 33 — 통신과 입력 확인 복구

2026-11-09 (Asia/Seoul). 독립 검토의 필수 제품 수정과 필수 helper·증거 보완은 각각 0건이다. 현재 PC의 사용자 native 확인을 수용했다. 수용 범위는 아래 네 통신·복구 경로와 사용자가 확인한 화면 동작이다.

## 배경과 변경 범위

상급 Stage4 M에서 113입력 뒤 `STAGE4_FUTURE_MESSAGE`가 표시됐다. 원 판의 Replay와 게시 시각이 남아 있지 않아 정확한 원인은 미확정이다. 정상 순서로 이력 두 건이 연달아 게시될 때의 읽기 경합이 유력한 가설이며, 통제 재현과 실제 발생 원인을 구분한다.

| 축 | 수용한 동작 |
| --- | --- |
| A. 게시와 읽기 | 기대 파일이 없으면 열거 뒤 그 파일을 재확인한다. 정상 연속 게시의 오탐을 막고 실제 순서 공백과 기존 메시지 검사를 유지한다. |
| B. 이력과 제안 | PROPOSAL을 받으면 이력을 다시 읽은 뒤 모델 사용 횟수를 대조한다. 이미 정해진 scope가 None으로 되돌아가면 거절한다. |
| C. ACK 미수신 | 실제 입력은 UNCONFIRMED 실패로 보존한다. 일치하는 owner의 프로세스·scope·채널 정리를 확인한 뒤 대기 상태를 해제한다. 늦은 신호와 입력 재적용을 차단한다. |
| D. 종료 표시 | 마지막 입력 ACK 수신과 worker 정리를 구분해 표시한다. 최종 완료 문구는 정상 기록과 실제 정리가 모두 결속됐을 때 표시한다. N-01의 중간 표시 한계가 남는다. |

검토된 변경은 `stage4_live_contract.py`, `stage4_live_job.py`, `stage4_live_ui.py`와 관련 시험 3개다. 수학, 정책, 추론 한도, 기본 indexed와 명시 K100K, R 목표, 엔진 및 Replay 형식은 Units30–32 기준과 같다.

## 검증과 사용자 수용

- 최종 동일 바이트의 고유 시험 47개가 통과했다. run04의 완료 22개와 run05의 완료 25개를 합한 수다. Main/Replay 메서드는 run04에서 시작한 뒤 외부 PID 목록 오류로 중단됐고, run05에서 처음 완료됐다.
- 누적 시험 시작 69, 완료 68, 통과 64, 수정 전 예상 실패 4, 외부 중단 1이다. 수정 전 UI 재현 2개는 이후 단언이 강화됐다. scope 후퇴 거절과 닫기 정산의 기준선 차이는 source 검토로 확인했다.
- 승인된 추가 실행을 포함해 supervisor 5회, Python image 26개, 실제 worker 8개다. 단위 시험의 메모리 policy 인스턴스 37개는 따로 센다. 입력은 알려진 55회와 중단 실행 상한 256회의 합인 보수적 상한 311회다.
- 5개 Job의 최종 active/member 0과 원 소유자 44개의 부재를 원시 기록으로 확인했다. PID 목록 재조회 helper는 최대 3회·시도 사이 5ms를 적용하며, 성공 실행에서 재조회 분기는 관측되지 않았다.
- 독립 검토는 네 축을 수용했다. 최종 후보 8파일과 검토 산출물 30개를 조율에서 대조했다. 사용자 native 통과는 같은 후보에 결속했다. 사용자가 확인한 통상 동작의 수용이며, 모든 장애 조합을 실행한 결과로 확대하지 않는다.

## 남은 검증과 후속 작업

- F-01 ACK 회복과 F-03 이력 경합은 이번 범위에서 해소됐다. F-02의 두 시계 통일은 후속이다. G-03의 runtime_policy 11개는 실행됐고, G-02의 마지막 입력 ACK에서 Replay 진입까지 이어지는 시험은 미실행이다. G-01·G-04는 별도로 남는다.
- N-01은 먼저 기록된 실패가 마지막 ACK 수신 직후 잠시 정리 중으로 표시되는 현상이다. 최종 상태는 실패로 복원된다. N-02의 Stage4 실패 필드와 N-03의 정리 차단 후 세션 내 복구도 후속이다.
- 사용자 113입력 판의 원인, run04 PID 목록 오류의 구체 원인, 재조회 분기의 OS 동작, 정확한 누적 입력 수, Fast 설정은 미확정이다.
- 상급 보드 전체 표시, 추측 설정 변경 후 안전한 Auto 재개, R 목표 UX, Stage4 확정·확률 표시를 후속으로 둔다. 메인 화면의 지원 정책 전체에서 실제 입력 뒤 안전칸·지뢰칸을 갱신할 때 기존 분석 결과를 재사용하고 표시 ON/OFF의 추가 비용을 대조한다.
- 일반 효율과 계산 지연은 별도 평가한다. 고효율 Replay는 행동 직전 공개 정보로 안전 효율, 불가피한 추측, 안전 대안이 있는 상태에서 선택한 위험을 구분한다. 전시 노트북·frozen 패키지·Production 수용은 별도다.
