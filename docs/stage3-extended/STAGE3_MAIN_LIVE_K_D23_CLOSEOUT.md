# Stage3 Main/Live 새 K(K_D23) 제품 반영 마감

기준일: 2026-11-21 (Asia/Seoul)

이 문서는 D 단계(추측 위험 선택 보강)에서 이번에 제품 범위로 확정해 Main/Live에 반영한 구성과 그 검증 범위를 적는다. 연구 후보 전체가 채택됐다는 뜻이 아니고, 일반적인 승률 향상이 증명됐다는 뜻도 아니다. 커밋 SHA와 원격 확인은 이 문서에 적지 않는다. 그 값은 반영 작업의 보고서에 있다(9절).

## 2. 기존 K 계열과의 관계

- K-P0, K-LC0, K-LC1은 정책 목록에 그대로 있고 선택, 전송, 입력 검증이 바뀌지 않았다. 새 K는 그 옆에 더한 정책이다.
- 새 K는 K-LC1의 원 선택을 한 번 만들고 그 위에서만 3절의 규칙을 적용한다. 규칙이 적용되지 않는 결정은 K-LC1의 선택 그대로다.
- 네 진입(새 판, 같은 보드 다시 플레이, 현재 판 인수, 깃발이 있는 판의 인수)과 첫 입력·준비 단계는 기존 K 계열의 경로를 쓴다. 새 판의 첫 칸 열기는 기존 K와 같이 추측 허용과 무관하게 입력된다.
- 여러 정책이 함께 쓰는 파일 `live_policy.py`, `live_k_policy.py`, `live_policy_job.py`, `live_policy_worker.py`, `live_analysis.py`, `ui_manager.py`, `ui_help.py`를 수정했다.

## 3. 선택 규칙의 지원 범위

| 갈래 | 규칙 | 적용 조건 | 한도와 범위 |
|---|---|---|---|
| 확정 입력 (D2) | 0이 증명된 칸을 먼저 연다 | 그 칸을 직접 열 때 확실히 열리는 칸들이 원 선택이 여는 칸을 모두 포함하고, 확실히 열리는 칸당 비용이 원 선택보다 낮을 때만 | 새 추론이나 후보 생성이 없다. 공개 정보의 배치만 쓴다 |
| 추측 (D3) 첫째 | 불가피한 50/50 쌍을 먼저 연다 | 두 칸 중 정확히 하나가 지뢰이고, 한쪽에만 닿는 주변 칸이 없거나 모두 확정 지뢰인 쌍이 증명될 때 | 증명된 쌍만 다룬다. 겉보기에 반반인 칸이 모두 불가피한 것은 아니다. 여는 칸의 지뢰 확률(50%)이 현재 최소 위험보다 높을 수 있다 |
| 추측 (D3) 둘째 | 동률 전방 선택 | 최소 위험이 같은 칸이 2개에서 8개일 때 | 각 칸을 연 뒤 다음 입력 하나까지 본 값만 비교한다. 호출 한도 72회. 후보가 8개를 넘으면 계산하지 않는다 |
| 추측 (D3) 셋째 | K-LC1의 추측 유지 | 위 둘이 아닐 때 | 계산된 최소 위험 칸 |

최소 위험 칸 선택은 그 한 입력의 위험을 가장 낮추는 선택이다. 판 전체에서 최적이라는 증명이 아니다. 동률 전방 값도 한 입력 앞까지의 제한된 값이며 판 전체 승률이 아니다.

## 4. 진단과 S1

- **pseudo 50/50 진단**: 서로 거울 관계인 두 칸을 찾아, 증명되면 판 전체에서 이기지 못할 확률의 하한을 보여 주는 별도 진단이다. 조건부 계산은 8회까지다. 조건 불충족, 한도 미검사, 범위 밖은 서로 다른 결과이며 어느 것도 pseudo 50/50이 없다는 증명이 아니다. 선택에 쓰지 않는다.
- **linked 풀림 진단**: 한 칸을 열고 살아남았을 때 다른 쌍 묶음이 풀리는지를 그 한 입력의 범위에서 계산하는 별도 진단이다(호출 한도 54회). 코드는 들어 있고 `PSEUDO_LINKED` 구성에서 실행된다. Live 기본 구성에서는 계산하지 않으며 화면에는 계산하지 않았다고 나온다.
- **S1**: 연구 단계의 후보다. 1,200개 보드 평가에서 실제 입력을 바꾼 보드가 9개뿐이어서 판정이 적용 부족이었고 제품 구성에 넣지 않았다.

## 5. 화면과 근거 기록

- 상태 줄에 짧은 이유가 나온다. **K 설명 펼치기** 단추는 새 K를 고르면 나타나고 처음에는 접혀 있다. 펼치면 선택 이유와 별도 진단이 읽기 전용 창에 나온다.
- 대기 중인 제안은 제안으로, 추측 허용이 꺼져 입력하지 않은 제안은 입력하지 않았다고, 엔진에 들어간 입력만 실제 입력으로 적는다.
- LOST로 끝나면 마지막 실제 입력의 입력 전 근거로 만든 패배 보조 설명이 붙는다. 패배 뒤 공개된 지뢰로 다시 판정하지 않고 기본 결과를 바꾸지 않는다. WON에는 설명이 붙지 않는다.
- 근거 기록(`K_D23_BASIS_V1`)은 PROPOSAL의 `basis`로 제안과 따로 온다. 세 역할을 섞지 않는다. 입력 허가는 VALIDATE와 ACK, 표시용 확정칸은 `info`, 선택 근거와 진단은 `basis`다. `basis`는 표시 전용이며 추천이나 입력 허가가 아니다.
- 근거 기록은 **앱 메모리에만** 있다. 대기 제안과 함께 보관했다가 함께 지우고, 마지막 실제 K 입력의 것만 종료 문구를 위해 그 판 동안 기억한다. 새 판, 같은 보드 다시 플레이, 정책 변경, 수동 입력 뒤에는 이전 설명이 남지 않는다.
- **Replay 파일에는 저장되지 않는다.** Replay에는 기존과 같이 실제 입력만 기록되며, Replay로 다시 볼 때 선택 이유와 진단은 나오지 않는다.

## 8. 확인하지 않은 것과 한계

- **전체 회귀를 실행하지 않았다.** 설명 시험의 도우미로 들어온 시험 모듈 4개의 자체 시험도 이번에 제품 경로에서 실행하지 않았다(설명 시험이 가져다 쓰는 부분만 실행됐다).

- 불가피한 쌍 선처리와 동률 전방 선택이 실제로 선택을 바꾸는 판, pseudo 조건이 성립한 판, linked 진단을 켠 구성의 native 관측. native에서 본 선택 이유는 최소 위험 칸 유지와 확정 입력뿐이다.
- 오류 종료 경로와 창 닫기가 거부되는 경로의 native 관측.
- 일반적인 승률 향상, 판 전체에서의 최적성.
- 진단 구성은 환경 변수로만 바꾼다. 화면의 사용자 설정이 아니다.
