## 9. Registered shared uncertainty method

### 9.1 Resampling unit

The resampling unit is the **scheduled primary board pair**, never actions,
decisions or repeated executions.

All evidence belonging to one board stays paired.

### 9.2 One shared replicate stream

G8, G5 and G9 use the **same 10,000 bootstrap replicate draws**.

For each replicate:

1. draw exactly `N` primary-corpus positions with replacement;
2. keep those `N` drawn positions as the shared replicate;
3. G8 evaluates the drawn boards that are WW;
4. G5 evaluates the drawn boards whose frozen CONTROL-defined G5 exposure flag
   is true **and** whose pair is WW;
5. G9 evaluates the drawn boards that are WW.

Subgroup membership is carried with the sampled board.

G5 does not separately resample only exposed boards.

This makes G8/G5/G9 intervals exactly reproducible from one draw stream.

Freeze:

```text
BOOTSTRAP_REPLICATES = 10_000
CONFIDENCE_LEVEL     = 95%
INTERVAL             = percentile
```

No BCa, adaptive replicate count or effect-dependent stopping.

### 9.3 Deterministic bootstrap PRNG

```text
BOOT_LABEL = ASCII("PROGRAM_K_E2_BOOTSTRAP_V1")

boot_seed_bytes =
    SHA256(BOOT_LABEL || 0x00 || protocol_seed || 0x00 || corpus_digest)

state0 = uint64_be_decode(boot_seed_bytes[0:8])
```

Use exact SplitMix64 with unsigned 64-bit wraparound:

```text
state = state + 0x9E3779B97F4A7C15 mod 2^64
z = state
z = (z xor (z >> 30)) * 0xBF58476D1CE4E5B9 mod 2^64
z = (z xor (z >> 27)) * 0x94D049BB133111EB mod 2^64
z = z xor (z >> 31)
output = z
```

Map each output uniformly into `[0,N)`:

```text
limit = floor(2^64 / N) * N
reject output >= limit
position = output mod N
```

Continue the same state stream after rejection.

Generate `N` accepted positions for replicate 0, then the next `N` accepted
positions for replicate 1, and so on through replicate 9,999.

### 9.4 Percentile endpoints

For each gate metric, sort the 10,000 **defined** replicate values.

Nearest-rank, no interpolation:

```text
lower_rank = 250   # 1-based
upper_rank = 9750  # 1-based
```

Use sorted zero-based elements `[249]` and `[9749]`.

Undefined-replicate rules:

- G8/G9: any replicate with zero WW -> that gate `DEFER`;
- G5:
  - if the observed primary sample has zero G5-exposed boards -> G5 is valid
    `NOT_APPLICABLE`;
  - otherwise, any replicate with zero exposed-WW observations -> G5 `DEFER`.

Do not silently discard undefined replicates.

### 9.5 Complexity / implementation

The bootstrap operates only on compact per-board scalar analysis records.

Its declared complexity is:

```text
O(BOOTSTRAP_REPLICATES * N)
```

At `N=10,000`, this is a bounded 100,000,000 accepted position draws plus
rejection overhead.

This bounded analysis is explicitly exercised in R0-B at Nmax and is not subject
to the one-streaming-pass rule that applies to durable-record reconstruction.

Exact observed corpus statistics are always reported even when a gate DEFERs.

## 12. G5 registered productive-FLAG regression gate

### 12.1 Why generic CHORD exposure is not enough

Generic "CONTROL executed a productive CHORD" exposure is too broad: frozen V1
normally reaches CHORD through physical flags, so such membership would mostly
restate the overall WW population and would not isolate the behavior that K-P0
changes.

G5 therefore uses CONTROL-only provenance for flags that **K-P0 intentionally
does not physically materialize**.

### 12.2 CONTROL FLAG provenance categories

For every executed CONTROL FLAG, retain enough frozen V1 decision/plan evidence
to classify that FLAG at the decision where it was committed as exactly one of:

1. **CONTROL_SETUP_CHORD_FLAG**
   - first committed input of a selected V1 setup plan whose terminal reveal is CHORD.

2. **CONTROL_FALLBACK_FLAG**
   - frozen §22 FLAG fallback with `decision.plan is None`.

3. **CONTROL_FLAG_TO_OPEN_SETUP**
   - first committed FLAG input of a selected V1 setup plan whose terminal reveal is OPEN.

If current frozen V1 evidence shows another reachable CONTROL FLAG category, E2
implementation qualification must stop and return to ChatGPT rather than silently
fold it into one of these classes.

K-P0 may still physically materialize category 1 under its frozen rule.

K-P0 does not physically materialize categories 2 or 3 merely as V1 marking/setup
behavior.

### 12.3 G5 exposure membership

A primary board is **G5-exposed** if CONTROL has at least one executed FLAG `f`
classified as either:

- `CONTROL_FALLBACK_FLAG`, or
- `CONTROL_FLAG_TO_OPEN_SETUP`

and, later in that same CONTROL run:

1. `f` remains physically FLAGGED;
2. CONTROL executes CHORD on an adjacent revealed clue `c`;
3. immediately before CHORD, `f` contributes to `c`'s physical flagged-neighbor set;
4. that CHORD directly reveals at least one safe cell.

Membership is defined from CONTROL evidence only.

It does **not** claim the earlier FLAG uniquely caused the later CHORD.

Report:

- number and fraction of primary boards exposed;
- number of qualifying FLAGs by provenance category;
- exposed WW count.

### 12.4 G5 metric / shared bootstrap

Let:

```text
D_W = G5-exposed boards where CONTROL and K-P0 both WIN
```

For the observed sample:

```text
mean_D_saving = mean(C_i - K_i for i in D_W)
```

G5 uses the **shared §9 replicate draws**.

For each replicate, use only sampled positions whose frozen G5 exposure flag is
true and whose sampled pair is WW.

G5 status:

- observed exposure count `0` -> `NOT_APPLICABLE`;
- any required replicate has zero exposed-WW observations -> `DEFER`;
- otherwise, if 95% lower bound `>= 0` -> `PASS`;
- if 95% upper bound `< 0` -> `FAIL`;
- otherwise -> `DEFER`.

Thus G5 fails only on a supported net Model-C regression in the behavior class
where K-P0 suppresses V1 physical flags that later prove useful to a productive
CONTROL CHORD.

## 23. Verdict framework / P-7 mapping

The frozen G1–G10 meanings remain those of the Program-K specification/protocol.

### 23.1 Gate status

- FAIL;
- DEFER;
- INCOMPLETE where required evidence/operation is missing;
- NOT_APPLICABLE only where this protocol explicitly defines it (currently
  G5 with zero observed G5-exposure).

### 23.2 Overall verdict classes

**IMPLEMENTATION_IDENTITY_FAIL**

A diagnosed source/harness/evidence/certificate/determinism defect invalidates
the qualified implementation identity.

It does not itself reject Program K as a research direction.

**INCOMPLETE**

Required evidence or scheduled mandatory units are missing/aborted/corrupt and no
higher-priority diagnosed implementation-identity failure already explains them.

**RESEARCH FAIL**

Under a complete, qualified identity, a registered research property is supported
as failed, including a G5/G8/G9 FAIL or another proven untenable frozen premise.

**RESEARCH DEFER**

Under a complete, qualified identity, support remains unresolved/inconclusive
under a registered gate.

**RESEARCH PASS**

Every required gate is PASS, except an explicitly valid G5 NOT_APPLICABLE.

### 23.3 Total precedence

If multiple classes appear simultaneously, overall classification is the first
applicable class in this exact order:

```text
1 IMPLEMENTATION_IDENTITY_FAIL
2 INCOMPLETE
3 RESEARCH FAIL
4 RESEARCH DEFER
5 RESEARCH PASS
```

Consequences:

- a complete supported G8/G5/G9 FAIL does **not** become a Program-K RESEARCH FAIL
  while other mandatory qualification evidence is still INCOMPLETE;
- first resolve the incomplete/identity condition under a separately authorized
  continuation/new run policy;
- no automatic retry is implied;
- only a complete qualified record may issue Program-K RESEARCH FAIL/PASS.

This avoids mistaking an incomplete implementation/qualification record for
an algorithm-level scientific conclusion.

### 23.4 Exact G8 DEFER causes

G8 has no discretionary "otherwise insufficient" clause.

G8 `DEFER` occurs exactly when:

1. observed `n_W == 0`; or
2. any shared bootstrap replicate has zero WW; or
3. the registered interval is neither wholly above nor wholly below the
   practical margin under §13.

Missing required records are `INCOMPLETE`, not G8 uncertainty.

### 23.5 E3 trigger

Prospective automatic E3 confirmation is allowed only when:

- E2 implementation/record is complete and qualified;
- G1–G4/G6/G7/G9/G10 are PASS;
- G5 is PASS **or valid NOT_APPLICABLE**;
- G8 is `DEFER` **solely because its interval overlaps the practical margin**.

E3 then uses a separately frozen independent corpus to resolve G8 uncertainty.

E3 never rescues:

- RESEARCH FAIL;
- IMPLEMENTATION_IDENTITY_FAIL;
- INCOMPLETE.

A G5 or G9 DEFER does **not** automatically trigger E3. Any follow-up for those
gates requires a separately justified and frozen protocol.

Broader generator/runtime claims also require separately frozen E3 confirmation
regardless of E2 PASS.
